# Новая версия (web/): единый дизайн, движение, адаптация. Главная как эталон

Решение владельца 24.11.2026. Эскиз Главной утверждён (страница-макет, телефон и ПК), команда «делай остальные разделы».

## Зачем
Новая версия на React уже повторяет все разделы старого сайта, но собрана без единых правил: 11 разных длительностей
анимаций, 9 разрозненных брейкпоинтов, плитки разной высоты, на телефоне провалы и яркое фото за текстом, логотипа нет.
Владелец хочет: 1) все анимации плавные и с одинаковыми, чёткими таймингами; 2) правильная работа на любом устройстве
(ПК с монитором 33″, iMac, iPhone 15/16 Pro Max, ноутбуки продавцов), телефон только вертикально; 3) вид в цветах
бренда Saif-Optics с логотипом и фото оптики на фоне.

## Цели / не цели
- Цель: одна система правил (цвета, сетка, движение), по которой переделываются все разделы, начиная с Главной.
- Цель: на телефоне владелец получает всю ту же информацию, что на ПК, но без тесноты: строки таблиц становятся карточками
  с главными полями, остальное по нажатию; графики те же данные, подписей вдвое меньше, подсказка по касанию.
- Не цель: менять расчёты и формат данных `docs` (они сверены со старым сайтом, сверки `web/scripts/*-parity.ts` должны
  сходиться как раньше).
- Не цель: альбомная ориентация телефона; выкладка новой версии (только по отдельной команде).
- Анти-цель: вторая система анимаций рядом с первой; анимации, которые задерживают данные.

## Ограничения
- Репозиторий публичный: никаких реальных сумм, имён, ключей в коде и примерах; тестовые данные только из `?demo`.
- Стек остаётся: React 19, Vite, Tailwind 4, shadcn/ui, Motion, Recharts, TanStack. Node в `C:\Users\user\.local\node`.
- Проверки: `npx tsc -b`, `npm run build`, сверки parity, скриншоты `web/scripts/shots.py` на ширинах 390, 768, 1440, 2560
  в светлой и тёмной теме; на телефоне не должно быть горизонтальной прокрутки.
- Ограниченная роль (продавец) видит только свою точку и разрешённые разделы — как сейчас.

## Варианты движка анимаций
1. **Motion (уже стоит) — выбран.** Перетекание «пилюли» (`layoutId`), посадка карточек, досчёт цифр делаются штатно;
   один движок, тайминги задаются токенами.
2. GSAP, как в роликах-референсах. Плюс: точь-в-точь код из роликов. Минус: +70 КБ и две системы движения в одном коде.
3. Чистый CSS без библиотеки. Минус: перетекание пилюли между элементами разной ширины и очерёдность посадки
   пришлось бы писать руками, повторяя то, что Motion уже умеет.

## Решения (как решено)

### Цвета и бренд
- Акцент: синий бренда `#026ea6` (с наклейки футляра), голубой колец логотипа `#09c0e4`, тёмно-синий `#223346`.
  В тёмной теме акцент светлее (`#27b3dc`), чтобы читался на тёмном стекле. Градиент колец логотипа как на старом сайте
  (`#9be8ff → #48bde0 → #1c8fc0`).
- Логотип-кольца (symbol `soMark` из `dev/base.html`) в шапке боковой панели на ПК и в верхней строке на телефоне; заставка
  при входе — та же, что на старом сайте (`dev/splash/saif-splash.js`).
- Фон: фото оптики `bg-day.webp` / `bg-night.webp` остаётся, тонировка сильнее, на телефоне ещё сильнее (≈0,9 непрозрачности).
- Тема: переключатель в шапке (солнце/луна), по умолчанию как в системе, выбор запоминается.

### Движение (один файл правил `web/src/lib/motion.ts`)
- Длительности: `fast` 0,2 с (нажатия, подсветка), `base` 0,36 с (передний край пилюли, сворачивание панели),
  `slow` 0,55 с (задний край пилюли), `land` 0,8 с (посадка карточек).
- Кривые: `out` = power3.out (0.215, 0.61, 0.355, 1), `inOut` = power3.inOut (0.645, 0.045, 0.355, 1),
  `expo` = expo.out (0.16, 1, 0.3, 1).
- Шаг между карточками 0,06 с. Посадка: из `opacity 0, y 26, scale 0.985` в исходное за `land` с `expo`, по порядку чтения.
- Цифры в плитках досчитываются за 0,6 с (кубическое замедление). Полоски и столбики вырастают за `land`.
- Пилюля меню и сегментов: передний край идёт первым (`base`, `out`), задний догоняет (`slow`, `inOut`).
- Смена раздела: уходящий гаснет за `fast`, новый приземляется посадкой карточек.
- `prefers-reduced-motion: reduce` — всё мгновенно. Все разделы берут тайминги только из `motion.ts`.

### Сетка (три режима вместо девяти точек)
- Телефон `< 640`: одна колонка, меню снизу (пять главных + «Ещё»), боковой панели нет.
- Планшет и ноутбук `640–1279`: две колонки, боковая панель свёрнута до иконок.
- Компьютер `≥ 1280`: до четырёх колонок, панель открыта (264 px); контент сводных разделов не шире 1600 px по центру,
  таблицы данных на всю ширину. На 33″ ничего не растягивается.
- Плитки одного ряда одной высоты, одинаковые внутренние отступы, скругление 24 px у плиток, 16 px у вложенных блоков.

### Главная (порядок по важности)
1. Шапка: логотип, «Главная», дата, кнопки Продажа / Расход / Пересчитать кассу.
2. Четыре плитки: Выручка сегодня (чеки, точки, сравнение со средним днём, искра); Касса сейчас (наличные на руках,
   «сходится» или расхождение, время пересчёта); Месяц к плану (сумма, кольцо %, осталось дней, нужно в день);
   Расчётный счёт (на утро, изменение за вчера, ближайший платёж).
3. «Требует внимания»: просроченные платежи, дни без листа или выписки, расхождение кассы, задания без ответа, опоздания.
   Пустой блок не показывается. Каждая строка ведёт в свой раздел.
4. Точки сегодня (выручка, чеки, продавец, полоска, месяц и % плана точки) и Выручка за 14 дней рядом.
5. Разделы по важности, по одной цифре каждый: Касса, Продажи, Отчёт р/с, Платежи, Задания, Аналитика, План, Линзы,
   Сверка, Склад, Пользователи. Тот же порядок в боковой панели.
6. Последние продажи.
На телефоне тот же порядок одной колонкой, разделы в два столбца (иконка над названием).

### Остальные разделы
В том же порядке важности, каждый на этих правилах: шапка раздела по одному образцу, плитки итогов, таблица → карточки на
телефоне, фильтры в выдвижном листе снизу, графики с подсказкой по касанию. Затем перенос «Пользователей» и «Заданий».

## Оставлено исполнителю
- Точные компоненты shadcn для выдвижного листа и подсказок; как именно хранить раскрытие карточек-строк.
- Какие поля таблицы каждого раздела считать главными на телефоне (по образцу: дата, точка, сумма, статус).
- Реализация «Требует внимания» по этапам: сначала то, что уже есть в `docs` (платежи, отчёт р/с, касса), потом задания
  и опоздания из таблиц `tasks` / `att_events`.
