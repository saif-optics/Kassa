# Исходники «Кассы Оптики»

Сайт `index.html` в корне собирается из этих файлов — правьте исходники, а не `index.html`.

```
bash dev/build.sh          # собирает ../index.html (на Windows: powershell -File dev/build.ps1 -Test — сборка + тесты)
python3 dev/test/t_audit.py  # проверка: ошибки JS, отступы, вылезание за экран (Playwright, тестовые данные)
```

- `base.html` — основная страница (касса, продажи, отчёт, аналитика, склад…)
- `patch_billz.py` — блок автозагрузки Сергели из Billz
- `patch_bz.py` + `bz/` — «Сверка», «Остатки Billz», «Перемещения»
- `patch_rs.py` + `rs/` — «Отчёт по расчётному счёту» (вкладка «Отчёт р/с»)
- `patch_fm.py` + `fm/` — «Фискальные модули» в «Отчёте р/с» и сверка «Фискальные модули ↔ Касса» (данные: `fiscal/<день>`, `settings/fiscal`)
- `patch_pay.py` + `pay/` — раздел «Платежи»: постоянные и разовые платежи, долги, что оплачено (данные: `payments/<id>`, `paymarks/<id>_<месяц>`; оплата ищется по словам в выписке р/с и расходах Кассы)
- `patch_att.py` + `att/` — вкладка «Пользователи» (data-tab `att`, раньше «Контроль»; для не-админа — «Приход»): сверху блок пользователей (его ставит `patch_role`), ниже журнал прихода сотрудников (`smena/admin.html`, режим `?embed=1`) во вкладке-iframe; вход и тема общие с сайтом
- `patch_role.py` + `role/` — статусы и права после входа (RPC `my_access` → `window.__sbRole`, `__sbPoint`, `__sbPerms`, `__roleLabel`, ставит `shim.html`): owner и admin — полный доступ и таблица «Пользователи» (`role/users.js`: группы по точкам, форма «Изменить», 11 переключателей прав); остальные (кассир, продавец, гость) — вкладки и элементы по правам `perms` (`sales_view`, `sales_write`, `exp_add`, `analytics` и др.), запись только через RPC. Проверка: `ROLE=seller|cashier|marketer|guestpt|sellernoatt|owner|admin python dev/test/t_role.py`
- `patch_tidy.py` + `tidy/` — применяется последним: плашки «в доработке» в Сверке и Складе, показ больших таблиц по 10–50 строк
- `patch_ui.py` — единый вид переключателей и стрелок (применяется последним)
- `test/t_native.py` — ищет «чужие» элементы: системные списки, даты, галочки, стрелки-символы
- `test/t_stress.py` — стресс на 20000 продажах (ROLE=marketer|cashier|seller|owner N=...): вход, аналитика, календарь, куча, ошибки; печатает JSON с метриками, запуск `build.ps1 -Stress`
- `shim.html`, `build.py` — вход и хранилище Supabase
- `splash/saif-splash.js` — заставка с логотипом при каждой загрузке (стиль iOS 26, светлая/тёмная тема); `build.py` встраивает её первой в `<head>`. Закрывающий тег script в этом файле писать нельзя
- `graph_src.py` → `graph-src/base.html.js` — зеркало JS из base.html (строки совпадают) для карты кода Graphify в `../graphify-out/`; пересоздаётся в `build.sh`
- `../supabase/functions/` — серверные функции: `billz-sync` (Сергели и C1 → Касса, точка в `body.point`), `billz-collect` (чеки, остатки, перемещения всех точек)

Supabase: проект `qvblxhyftwivkzxucfak`. Расписание (pg_cron, по Ташкенту): выгрузка Billz в 20:00, Сергели в 20:02, C1 в 20:04; повторы в 20:20 и 21:00 (пропускаются, если после 19:50 уже была удачная загрузка).
Тестовые данные в `test/fakesb_synth.js` — вымышленные.
